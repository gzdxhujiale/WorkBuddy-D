# Design: Refactor and Consolidate Main Specs

## Context

详见 `proposal.md`。当前 `openspec/specs/` 存留 14 个主规格文件。项目架构已经建立清晰的分层权威文档：
- `ARCHITECTURE.md`：定义系统边界、多 Webview 拓扑与进程通信。
- `docs/FRONTEND.md`：定义 React 19、TanStack Router/Query、Zustand、Tiptap、组件与状态工程。
- `docs/BACKEND.md`：定义 Go/PostgreSQL、RLS、数据迁移、连接池与服务边界。
- `docs/DESIGN.md`：定义双视觉主题、5-Level Elevation、布局间距与设计令牌。

目前规格层与工程层边界模糊，且充斥大量因修复过去缺陷而写下的负向否定式禁令。本设计定义如何通过确定的拓扑映射、正向重写模式以及零行为漂移的验证门禁完成主规格治理。

## Goals / Non-Goals

**Goals:**
- **拓扑收敛**：将 14 个离散规格合并重构为 7 个标准业务能力领域，消除目录与概念冗余。
- **技术解耦**：彻底剔除规格中的类库名称（Tiptap、pgxpool、TanStack Query）、DOM 标记（dataset.themeStyle）与内部 IPC 频道字符串。
- **正向行动化重构**：将所有“严禁/不得/避免/杜绝”等负向表述转化为以 `SHALL/MUST` 为主词的正向状态守恒契约，彻底消除诱发 LLM 幻觉的“粉红大象”陷阱。
- **100% 场景保真与合规**：确保合并后业务场景完整覆盖原有需求，且通过 `openspec validate --specs` 自动化校验。

**Non-Goals:**
- 不修改任何应用端（React/Go/Rust）运行时业务逻辑或接口行为。
- 不修改 `openspec/config.yaml`（严格遵守用户约束）。
- 不破坏现有通过审核的业务事实或变更数据模型。

## Decisions

### Decision 1: 7 大标准能力领域拓扑收敛矩阵

*备选方案*：保留 14 个目录仅做内容文字修改。
*弃用原因*：保留碎片化目录会导致未来的变更继续在孪生目录间（如 `daily-review` vs `daily-review-intelligence`）产生困惑与重复，无法从根本上治理目录结构。

### Decision 2: “正向行动化不变量”改写范式 (Affirmative Transformation Paradigm)

在重写需求与场景时，严格遵循四步转换机制：
1. **识别负向句式**：抓取包含“严禁、不得、避免、杜绝、绝不、控制台不抛异常”等句式。
2. **定位历史 Bug 疤痕**：判断该否定是否源于某个历史缺陷（例如“不得在查询中使用 deleted_at 字段”）。
3. **推导正向不变量**：提炼系统在此边界下应当保证的正向业务事实（例如“系统仅基于 user_id 与日期检索权威记录”）。
4. **统一 Normative 关键词**：严格使用 `SHALL` / `MUST` 定义正面作为，场景使用标准 `GIVEN / WHEN / THEN`。

### Decision 3: 技术选型与实现细节归位策略

- 移除任何第三方库名（例如将“Tiptap 富文本文档”改写为“结构化富文本文档树”，“pgxpool 连接池”改写为“服务端有界数据库连接池”）。
- 移除具体 DOM 类名与操作（例如将“给 document.documentElement 挂载 theme-retro-pixel 类名与 dataset.themeStyle”改写为“系统持久化用户选择的主题风格，并向所有已打开的桌面 Webview 窗口实时广播主题切换通知”）。
- 移除具体 UI 像素方位（例如将“右上角”、“右侧月历”、“侧边栏刷新按钮上方”改写为逻辑功能组件“在打卡日历视图中”、“在侧边栏常驻快捷唤起入口中”）。

## Risks / Trade-offs

- **[Risk 1: 整合过程中意外遗漏关键业务场景]**
  - *Mitigation*: 逐一建立新旧需求与 Scenario 映射清单，在 tasks 中采用逐能力合并核对，确保原有 40+ 个测试场景在 7 个新规格中均能找到严格对应的语义。
- **[Risk 2: 重构后的规格文件格式违背 OpenSpec 验证要求]**
  - *Mitigation*: 每个规格编写完成后立即运行 `openspec validate --specs`，严格确保 `### Requirement:`、`#### Scenario:`（4级标题）、WHEN/THEN 格式完全合规。
