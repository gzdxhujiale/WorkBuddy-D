# Proposal

## Why

在 WorkBuddy-D 当前实现中，项目阶段与任务的关系呈现为彼此隔离的“独立任务文件夹”，任务被静态限制在单一阶段内，无法体现工序流水线（Pipeline）推进的真实业务逻辑。此外，用户在阶段内添加或整理任务时依赖单一表单窗口或单行输入框，缺乏类似 Markdown 任务列表的高效批量录入与编辑体验。

为了降低任务拆解摩擦并提供符合直觉的工序推进机制，本项目引入阶段任务自动流转生命周期、阶段历史快照保留、反向退回机制、右键直接完成以及基于 Tiptap 模态弹窗的批量任务清单管理。

## What Changes

- **阶段任务自动流转生命周期**：在非末尾阶段点击勾选任务时，任务自动流转到下一个阶段，并在上一阶段留下已完成历史快照；进入新阶段的任务状态重置为待办，且静默自动对齐新阶段的默认负责人与排期时间。
- **终局阶段完成与项目进度联动**：仅当任务在最后一个阶段被勾选完成，或通过右键菜单直接完成时，该任务才被标记为真正的全局已完成（`completed: true`），同时联动推进项目整体完成度并在四象限/今日待办归入已完成历史。
- **任务阶段回退支持**：在非初始阶段的任务卡片菜单中提供“退回上一阶段”动作，以纠正误触流转操作并清理或恢复阶段快照。
- **右键上下文菜单快捷直达**：在阶段任务卡片上增加右键上下文菜单，支持“直接标记完成”跳过后续阶段工序，以及“退回上一阶段”、“删除任务”。
- **基于 Tiptap Modal 的阶段任务批量管理**：在每个阶段卡片头部新增“管理任务”按钮，点击呼出 Tiptap 模态弹窗。支持以 `- [ ]` 任务列表形式批量回车新增、退格删除、编辑标题与勾选流转，关闭或提交时双向同步至任务持久层。

### Non-goals（非目标）
- 不改变独立非项目任务（Standalone Tasks）的四象限归属与生命周期规则。
- 不引入无限层级的复杂子工序工作流引擎，保持单级流水线阶段有序推进模型。
- Tiptap 任务管理弹窗不替代完整属性编辑弹窗（`TaskQuickEditWindow`），排期、提醒等高级元数据仍由快捷编辑窗口管理。

### Modified Capabilities
- `project-management`: 扩充阶段流水线任务流转规则（Stage Pipeline Progression）、已完成阶段历史快照（Stage History Snapshot）、阶段回退动作（Stage Rollback）以及多阶段终局完成度联动。
- `task-management`: 扩充阶段内快捷勾选流转与右键直达完成状态机、基于 Tiptap 任务列表的模态弹窗双向投影同步管理。

## Impact

- **前端交互与组件**：`ProjectStageBoard.tsx`、阶段卡片组件、新增 `StageTaskManagerModal.tsx`（封装 Tiptap TaskList 批量编辑器与实体 Diff 解析）。
- **数据结构与服务层**：扩展前端 `ProjectTask` 类型及流转状态字段（如阶段历史记录/快照标志），调整 `useProjectActions` 中 `saveTask` 与批量任务同步逻辑。
- **后端持久化与接口**：评估任务表是否需要记录阶段历史快照或流转元数据，确保批量更新接口与并发版本控制（`lock_version`）一致性。
